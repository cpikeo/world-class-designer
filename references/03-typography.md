# 字体系统与排印执行

本文件拥有：字体性格判断、文字角色、层级编码、尺度关系、行长行距、断行与文本块轮廓、CJK 禁则与标点、中西文混排、数字注释、排印肌理、编辑性元素、屏幕与移动端排印、渲染验证。版面结构与层次分工见 `02`。

排印要把语义、字形性格、文本块轮廓、层级、行长、断行、字重、间距、位置与色彩组织成可读、有辨识度的系统。

## 一、修正顺序

**内容与语义 → 信息层级 → 文本块与版心 → 字体角色与字形 → 断行与行长 → 行距/段距/字距 → 字号与细节。**

字号缩小、字距拉开、整段加粗都不是默认补救。先判断问题出在文案、层级、容器还是字形执行。**一页文字读不顺，多数原因不在字体。**

## 二、怎么读一款字体

不要用形容词选字体（“优雅”“大气”“高级”无法执行）。看六个可观察变量：

| 变量 | 观察什么 | 意味着什么 |
|---|---|---|
| 骨架与中宫 | 笔画是否向中心聚；字面周围留白多少 | 中宫紧 → 内敛、正式、小字耐读；中宫松 → 开阔、有力、适合远读 |
| 字面与字重分布 | 字面积占字身比例；笔画粗细是否均匀 | 字面大 + 均匀 → 密度高，适合信息型；字面小 + 有对比 → 从容，适合文学型 |
| 横竖对比 | 横画与竖画的粗细差 | 对比明显（宋/明朝）→ 有书写血缘、庄重、静态；等粗（黑体/无衬线）→ 中性、当代、不抢内容 |
| 笔形起收 | 顿笔、挑、钩、切角、圆头 | 锐利起收 → 传统、有工具痕迹；平切圆头 → 工业化、当代 |
| 重心高低 | 字的视觉中心在字身中的位置 | 重心高 → 轻、上升，适合标题；重心低 → 稳、沉，适合正文 |
| 整段灰度 | 排成整段后是均匀的灰，还是有斑驳、亮点、暗块 | 决定它在长文里的表现；有个性的字体在小字号下常会碎 |

**首要判据不是性格，是灰度。** 在目标尺寸与目标观看距离下排一段真实文案，看它是否均匀。碎掉的字体，性格再好也不能用于正文。

**这三项必须在实际渲染里看，不能在字体选单里看**〔硬〕：字体名称与厂商示意页都会掩盖真实表现。

1. **字重是否真的存在。** 只有 Regular 与 Bold 的家族，做三级层级时会触发合成加粗（fake bold），笔画糊、字宽外扩。检查：把三档并排放在目标尺寸看笔画边缘，合成加粗会出现笔画粘连与字形变形。
2. **字符是否被回退。** 字体不含某个字（生僻字、异体字、箭头、上下标数字、货币符号）时，渲染引擎静默换字，行内出现粗细与字面高度不一致的“补丁”。检查：把全篇用到的特殊字符集中排一行看。
3. **标点与字距是否被引擎改动。** 中文两端对齐、标点挤压、字距调整会改变实际行长与断行点。设计软件画布与实际输出引擎的处理不同，要看最终产物。

## 三、字体性格与失效场景

不是禁令，是“何时要付什么代价”。选择时应能说出代价。

| 字体类型 | 语言倾向 | 失效场景 |
|---|---|---|
| 宋 / 明朝 | 庄重、时间感、文学、权威、文化厚度 | 极小字号横画消失；低分辨率投影变灰；需要强冲击的标题过于静态 |
| 黑体（现代无衬线） | 中性、当代、效率、系统感、不抢内容 | 需要文化厚度或手工感时显得平淡；过细字重在投影上直接消失 |
| 仿宋 / 楷 | 手写血缘、东亚传统、公文气质、亲切 | 与几何无衬线混用会割裂；字重档位少，做不出三级层级 |
| 圆体 | 柔性、消费、亲和、轻 | 严肃议题、需要权威的证据页会失重 |
| 拉丁 Garalde / Transitional | 温和、可读、书籍长文 | 需要强当代感时显得旧 |
| 拉丁 Didone | 高对比、时尚、奢侈品 | 小字号横线消失；屏幕渲染易断 |
| 拉丁 Grotesque（Helvetica 类） | 中立、系统、瑞士式 | 极易平淡；默认选择，往往是没有选择 |
| 拉丁 Humanist（Frutiger 类） | 更易读、柔和、导视友好 | 需要锐利感时不够有力 |
| 拉丁 Geometric | 现代、纯粹、建筑感 | 小字辨识差（a/g、i/l 相近） |

**数量纪律**〔验〕：一套排印系统通常一到两款家族足够；新增字体需要承担现有字体无法合理承担的角色，否则是噪音。多字体带来的“丰富”，读者感知到的通常是“不统一”。但这条有反例——双语出版物、档案复刻、多语言产品需要按文种各配一款，此时“两款”不是上限。

**不要用字体给内容贴性格。** 字体性格是二阶效应：读者先读到内容，才会感到语气。用字体弥补内容空洞，只会得到“排版很用力但没说什么”。

## 四、文字角色与层级编码

先定角色，再定字号。角色由职责定义，不由大小定义。

常见角色：**主张（标题）｜导语（deck）｜正文｜引文｜证据/数据｜标签｜注释｜导航（页眉页脚页码）**。

为每个角色记录：语义职责、实际字体与回退、字重、典型尺度、行距/段距、断行规则、允许变化。只记录影响复用的决定，不建立无人使用的庞大字级表。

**四种编码手段及其代价**：

| 手段 | 优点 | 代价 |
|---|---|---|
| 字号 | 最直接，跨越观看距离仍成立 | 最耗空间；层级多时把版面拖散 |
| 字重 | 不占空间，可密集使用 | 字重档位少的字体只能做两级，第三级失效或触发合成加粗 |
| 空间（前后距、缩进、分栏、位置） | 最优雅，视觉噪音最低 | 需要读者自己发现分组，太微妙就失效 |
| 颜色/明度 | 最省空间 | 超过主/次两级就沦为装饰，且损对比度 |

**用法**：主张与正文之间用两种手段（常见为尺度 + 空间）；同级之间只用一种（通常空间）。所有层级都用同一种手段，读者只会看到“一串差不多大的字”。

本表处理**文字内部**的层级编码；元素之间该在哪里花视觉重量，见 `02`「层次反差」。先由版面决定重量，再由本表决定实现方式。

## 五、尺度关系

不存在通用比例。尺度由三个变量决定：**观看距离 × 文本长度 × 与主体的关系**。

- **可辨台阶**〔验〕：两处文字的字号差太小时，读者不会读成两个层级，只会读成“排得不整齐”。这个“太小”的临界随字体、字重、观看距离和目标尺寸变化——同字号下，字面大的字体看起来更大；投影距离下，同样的差值会消失。**验证方法**：把候选字号并排渲染，缩到目标尺寸（投影按后排视角、手机按实机宽度），眯眼判断能否一眼分出两级。判断不了就加大差距。

一次实际渲染观察〔验〕：Microsoft YaHei、正文 17px、标题字重 700 与正文 400 并置时，标题为正文的 1.10 倍与 1.20 倍仍被读作“加粗的正文”，1.35 倍才成为独立层级；缩到 320px 宽后，1.10–1.35 的差别基本消失，仍可辨的反而是**文本块的形状与行数**。结论有两条：字号台阶的临界随字体、字重、观看尺寸移动，不能定为通用比例；低分辨率场景下，层级往往靠块形与行数承担，而不靠字号。
- **标题的三项决定**：观看距离（投影/手机/印刷差数倍）、标题字数（字数越多，可用字号越小）、与主体的关系（标题是否要盖过图像）。
- **大标题的成本**：字号越大，断行越难、字距越需要收紧、轮廓越容易暴露问题。标题行数增加会推迟读者进入正文的时点——需要快速进入内容的页面，先用文案解决，不要靠缩小字号硬塞。
- **极小字号**：注释与元数据可以很小，但必须在目标距离可读〔硬〕。投影与远距离场景里的极小字号是无效设计，不是精致。

## 六、行长、行距、段距

- **行长按字数判断，不按毫米。** 中文连续正文有回扫极限：行长增加，眼睛回到下一行开头时的搜索成本上升，容易错行或重读。栏越宽，回扫成本越高；移动端应更短。**判断方法**：读一段真实文案，看眼睛有没有在同一行停顿两次。
- **经验区间**〔验〕：中文正文单行常见在 25–40 字之间，宽栏大字号偏下限，窄栏小字号偏下限以下就需要缩栏。这是起点不是标准，最终以回扫测试与目标媒介为准。
- **行距与行长联动。** 行长增加，行距通常要跟着增加，否则回扫会错行。行距同时是密度旋钮：信息型收紧、文学型放松。但行距不能补偿坏断行——断行错了，加行距只会让错误更明显。
- **段距与首行缩进通常二选一，但不是绝对。** 缩进是传统中文（及日文）的段落标记，段距是现代与西文的做法。选择的依据是**出版类型与阅读传统**：书籍正文、古籍整理、部分文学类出版物用缩进；报告、网页、演示、产品文档用段距。同一层级内不混用——这是为了避免读者数不清段落起止，不是为了遵守款式。两种同时出现是成立的，但要各自承担不同职责：缩进标记段落，段距标记区块（如原文／译文并列、正文与例证、多作者分栏）。职责一旦重叠，段落信号就失效。
- **密度的真实来源**是行长 × 行距 × 字号的组合，不是行距单项。想变密，先缩短行长，再收行距；想变疏，先放宽行长（在可读范围内），再放行距。
- **栏宽与栏距**：栏距明显小于行距的视觉重量时，读者读成“同一块”；明显大于时读成“两栏”。介于两者之间最危险——读者不知道是否该跨栏读。

## 七、断行与文本块轮廓

**断行是设计动作，不是排版软件的默认结果。**

- **中文按语义单位断**：专名、术语、数量+单位、否定词与被否定内容、介词短语与宾语、连词与从句，都不能被拆开。断在语义接缝处，读者不觉；断在词内，读者会重读一次。
- **避头尾（禁则）**〔硬〕：句读标点、闭引号、闭括号、百分号、单位符号不得出现在行首；开引号、开括号不得出现在行尾。中文排版引擎多数支持，但导出的 PDF、网页与 PPT 行为不一致，必须看最终产物。
- **避免**：**孤字**（一行只剩一两个字）、**孤行**（段末只剩很短的一行）、标题最后一行比第一行更长。
- **标题轮廓**是四种可设计的形式：

| 轮廓 | 效果 | 何时用 |
|---|---|---|
| 满宽齐左 | 稳重、信息型，靠内容本身的力量 | 标题短、版面需要一个稳定的顶边 |
| 阶梯／跌级（逐行渐短） | 形成一条向下的坡，把视线送到正文 | 标题较长，需要垂直推进 |
| 短行悬置（末词单独成行并拉开） | 制造停顿与强调 | 标题极短，且有一个词值得被单独看 |
| 齐右／居中 | 仪式感、对称、碑刻感 | 标题短、版面本身对称，或封面/章节页 |

- **悬挂标点与光学边距**：中文的引号、括号、句号在行首行尾会造成视觉凹口。专业排印会让标点外挂，使“字”的边缘看起来齐。检查方法：眯眼看左边缘，是否有节奏性的小缺口。这属于最高一档的工艺，收益在近看时才显现。
- **标题断行后的形状本身在说话**：一个倒三角、一个方块、一条单行，传达的语气完全不同。选定轮廓后再调整字数。

### 断行示例

标题“生成式 AI 基础设施正在进入回报验证期”不应把“生成式 AI”或“回报验证”拆到两行。优先按“生成式 AI 基础设施 / 正在进入回报验证期”组织语义，形成两行等重的块；若实际字体与栏宽导致溢出，先调整文本块或精简文案，不靠任意断词解决。若改成“基础设施进入回报验证期”，则可用单行满宽，把“生成式 AI”降为导语——改文案常常比调字号更有效。

## 八、中西文混排

- **字号匹配的实质**：CJK 字面约等于 1em，拉丁大写高约 0.7em、小写 x-height 约 0.5em。同字号并排时中文看起来比西文“大一号”。要判断的是**视觉字面高度**是否一致，不是名义字号是否相同。常见做法是让西文名义字号略大于中文，或选 x-height 较大的西文字体。
- **字体回退顺序**：西文字体在前、中文字体在后，让拉丁字符用西文字形、CJK 用中文字形。顺序反了会出现“用中文字体排的西文”，宽度、字形、标点全都不对。
- **基线**：中文字身通常小于 em 框，与拉丁基线对齐时会略微悬浮或下沉。混排段落要在实际渲染里看基线是否平齐，而不是看字体参数。
- **西文与中文之间的间隙**：不是一个空格的问题，而是一个视觉间隙。太小会粘连，太大像断句。按字体与字号判断，不写死是否插入空格。
- **标点**：中文用全角标点，西文用半角；不要出现“中文句子里的英文句点”。数字用半角。全角标点在中文两端对齐时会被引擎挤压，导致视觉宽度不一致——看最终产物再决定是否手动锁标点。
- **斜体**：中文没有真正的斜体，伪斜体是机械倾斜，会让字形失真。强调优先用字重、着重号、位置或颜色。

## 九、数字、表格与注释

- **等宽数字（tabular）**用于需要纵向对齐的表格与多行数据；**比例数字**用于正文与标题（字距更匀）。先验证字体是否真的提供两套——不少字体把小写数字写死为一种。
- 小数点、千分位、正负号、百分号、单位位置应全篇一致。比较数字时检查位数与小数点是否对齐。
- **大数字的排版**：用单位解决数量级（亿/万/×10⁹），不在正文里堆零。一个被放大的数字，其单位应显著小于数字本身，且紧邻。
- 对齐优先级（数字）：小数点对齐 > 右对齐 > 左对齐。
- 表头、单位、来源、注释应与数据建立明确关系，不能因缩小而失去可读性。来源与口径属于正文的组成部分，不是可省略的装饰。
- 上标、脚注、交叉引用在最终格式中仍需可读、可定位；注释编号系统全篇一致。

## 十、排印肌理

排一页文字，眯眼看应当是**均匀的灰**。出现以下现象说明断行或对齐有问题：

- **白斑**：多行短行叠加形成的亮块。
- **暗斑**：某些行被挤压，或字重不一致形成的深块。
- **河流**（rivers）：词间距连成的白色竖向通道，多见于两端对齐的窄栏。
- **斜线纹理**：连续多行以连字符结尾，形成一条可见斜线。

**两端对齐的策略**：中文两端对齐相对安全（可微调字距与标点），但需控制标点挤压与字距累计——一味拉字距会让行内出现疏密不匀。拉丁窄栏 + 长词 + 无连字符会产生河流，此时改用左对齐或允许连字符。连字符是拉丁文的必要工具，但需限制连续连字符行数。

## 十一、编辑性排印元素

这些元素决定作品“像不像出版物”，而不是“像不像幻灯片”。

| 元素 | 职责 | 使用条件 |
|---|---|---|
| 首字（drop cap / raised cap） | 标记文章起点、建立入口 | 版面留得出空间，且确有一个明确的“开始”；缩进段落不用 |
| 引文（pull quote） | 让快速翻阅的人抓到论点 | 应真的出自正文；同一跨页通常不超过一处；尺度放大 + 位置偏置，不是加引号加粗 |
| 图注 | 说明图像是什么、谁拍的、何时、有何限制 | 与图同宽或略窄，字号小于正文，位置全篇统一，不能离图太远 |
| 旁注（marginalia） | 提供不打断主线的补充 | 外边距真的够宽；不够宽时它只是挤压 |
| 页眉 / 页脚 / 页码 | 导航与定位 | 位置、字号、对齐全篇一致；不与内容争注意力 |
| 目录 | 信息架构的自我说明 | 编号、引导线、页码对齐是基本功；条目文字应反映真实章节职责 |
| 分栏标题（running head） | 让读者知道自己处在哪一节 | 需要真实的章节结构，不能为装饰而设 |

## 十二、屏幕与移动端排印

屏幕排印的失败与印刷不同：它不发生在纸上，发生在**字体加载、布局重排和像素渲染**这三个环节。

- **字体加载**：Web 字体会经历“先隐形再显示”（FOIT）或“先回退再替换”（FOUT）。两者都会造成布局跳动，且回退字体的字面高度、字宽与目标字体不同，替换瞬间整段行长与断行全变。要求：按目标网络与设备实测加载过程，而不是相信字体服务的默认行为；关键文案的可用性不能依赖 Web 字体加载成功。
- **文本扩张**：同一段话在不同语言、不同系统字体、不同字体版本下长度差异显著。布局必须容纳**实测最长文案**，不能用设计稿里的占位文字估长度〔硬〕。
- **用户字号**：系统级字号放大后，固定高度的容器会溢出、固定行数的标题会截断。检查时把系统字号调到用户可设置的较大值再跑一遍。
- **像素渲染**：细字重在低 DPI 屏幕上会发虚甚至消失；暗底亮字会有光晕效应（halation），实际视觉字重比亮底暗字更粗。字体在 1x 与 2x/3x 屏上的表现不同，需分别看。
- **动态尺度**：移动端首屏的字号受屏幕宽度限制，标题的断行应在真实设备宽度下验证，不能在缩放过的画布里验证。

## 十三、故障与优先处理

| 故障 | 先查 | 优先动作 | 不要先做 |
|---|---|---|---|
| 标题不突出 | 文案是否明确、占幅是否足够、位置是否有效 | 精简主张，调整文本块与位置，再调字号字重 | 加粗、加下划线、加色块 |
| 标题像一堵墙 | 语义是否过长、断行是否任意 | 改写或拆分文案，设计断行与轮廓 | 缩小字号塞进一行 |
| 正文难读 | 行长、密度、对比、行距、阅读距离 | 重分组，调栏宽与文本块，再微调字级 | 换一款“更好看”的字体 |
| 中文标题断行生硬 | 语义单位、专名、标点、标题形状 | 先改文案或栏宽，再控制断行 | 手动插入空格撑开 |
| 中西文混排参差 | 字面高度、基线、字体回退、字重映射 | 在实际渲染环境校准视觉字面高度与基线 | 只按名义字号对齐 |
| 数字列不齐或难比较 | 位数、精度、单位位置、数字宽度 | 统一格式、精度、单位与对齐方式 | 手动加空格凑齐 |
| 页面充满近似字号 | 文字角色是否真的不同 | 合并无实质差异的层级，用空间与位置建立关系 | 再发明两个新字号 |
| 整页读起来“毛” | 断行、词距、行距是否互相冲突 | 先修断行，再调词距，最后动行距 | 全篇拉开字距 |
| 文字在图上读不清 | 图像最亮/最暗区域的实际对比 | 改裁切、改文字位置、局部压暗或提亮 | 给文字加半透明底板 |

文字压图时的对比判定与取样方法，见 `04`「裁切与文字避让」与 `07`「证据口径」。

## 十四、渲染验证

字体是最容易“本地好看、交付崩坏”的一环〔硬〕。源文件正常不代表 PDF、其他系统或浏览器中正常。

**顺序**：先在目标媒介导出真实产物 → 再按目标尺寸与距离看 → 最后才回设计文件改。媒体层面的完整检查清单见 `06`；本节只列**字体特有的崩坏方式**：

- **未嵌入 / 被替换**：字重与字形静默改变，伪粗体代替真粗体，字形宽度变化导致断行全部移位。
- **字符覆盖不全**：生僻字、异体字、符号、上标回退到其他字体，行内出现粗细不同、基线不齐的“补丁”。
- **避头尾失效**：标点跑到行首，或开括号留在行尾。不同引擎（InDesign / Word / 浏览器 / PPT）行为不一致。
- **两端对齐的标点挤压**：同一段中文在不同引擎下标点宽度不同，行长与断行随之改变。
- **加载与回退**：Web 字体未加载时用回退字体排版，替换瞬间版式跳变；系统字号放大后固定容器溢出。

没有实际检查时，明确标注未验证，并说明未检查的环境。**不要用设计软件的画布代表渲染结果。**
