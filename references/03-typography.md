# 字体系统与排印执行

本文件拥有：字体性格判断、文字角色、层级编码、尺度关系、行长行距、断行与文本块轮廓、CJK 禁则与标点、中西文混排、数字注释、排印肌理、编辑性元素、屏幕与移动端排印、渲染验证。版面结构与层次分工见 `02`。

排印要把语义、字形性格、文本块轮廓、层级、行长、断行、字重、间距、位置与色彩组织成可读、有辨识度的系统。

## 一、修正顺序

**内容与语义 → 信息层级 → 文本块与版心 → 字体角色与字形 → 断行与行长 → 行距/段距/字距 → 字号与细节。**

字号缩小、字距拉开、整段加粗都不是默认补救。先判断问题出在文案、层级、容器还是字形执行。**一页文字读不顺，多数原因不在字体。**

## 二、怎么读一款字体

不要用“优雅、大气、高级”代替观察，也不要由单个字形直接推出用途。把候选字体排成同一组真实文本，在相同名义字号、字重、栏宽与输出环境中比较：

| 观察维度 | 中文与西文分别看什么 | 对决策的实际影响 |
|---|---|---|
| 骨架、中宫与字腔 | 中文字画收放、内外白；西文 aperture、字腔开放度与字宽 | 影响小字辨识度、标题轮廓与文本块密度；不直接等于“正式/亲和” |
| 字面率与视觉高度 | 中文字面占字身比例；西文 x-height、大写高、升降部；混排时比较实际墨迹高度 | 同字号并不同大；决定视觉级差、行距与混排补偿 |
| 笔画对比与最细处 | 横竖/主副笔画对比、连接处、最细横画与衬线 | 决定低 DPI、投影、纸张吸墨与反白时的风险 |
| 字重与宽度轴 | 真实字重是否成体系；可变字轴是否被当前软件支持；窄体是否牺牲字腔 | 决定层级手段与空间成本，不能只看家族宣传中的档数 |
| 笔形、重心与方向 | 起收笔、切角、曲线张力、视觉重心、倾斜是否专门设计 | 形成语气与动势；需结合内容和整段效果判断 |
| 数字与符号 | 0/O、1/I/l、6/8、小数点、货币、上下标、箭头；是否有表格/比例、 lining/old-style 数字 | 决定数据识别、对齐与混排一致性 |
| 整段灰度与节奏 | 均匀度、暗块、白斑、字间节奏、回扫、标点造成的凹凸 | 判断长文与窄栏；单字漂亮不能证明整段成立 |

这些观察只产生候选与风险假设，不生成“中宫紧就适合正文”“无衬线就中性”的定律。字体语义还受内容、字号、字距、媒介和文化经验影响。

**输入—决策—失败信号**：先确定文字角色、真实文案、目标尺寸和渲染环境，再比较候选；若整段出现斑驳、小字粘连、细画消失、混排跳动或远距层级消失，应换字重/字体或调整文本块，而不是继续加装饰。

### 名称之外的四项核验

1. **真实字重与实例**：检查当前输出是否调用了目标字体文件和字重实例。合成加粗、伪斜体或可变字轴被静态化时，改用真实实例或其他层级手段。
2. **字符覆盖与 shaping**：集中检查生僻字、异体字、组合字符、emoji、箭头、上下标和货币；拉丁连字、印度/阿拉伯等复杂文字还依赖 shaping 引擎，不能只查码位存在。
3. **字体度量与回退**：比较目标字体与回退字体的 advance width、x-height、大写高、ascender/descender 和默认行框。名称相同的不同版本、不同操作系统hinting 与渲染引擎也可能改变字宽、基线和断行。
4. **最终引擎行为**：标点挤压、两端对齐、连字、禁则、字距和文本缩放会改变结果。设计软件画布、浏览器、Office、PDF 阅读器与印前 RIP 不是同一个排版引擎。

## 三、字体性格与失效场景

类别只帮助提出假设，不能替代具体家族与真实输出的判断。

| 字体类型 | 可探索的语言倾向〔境〕 | 优先检查的风险 |
|---|---|---|
| 宋 / 明朝、拉丁 Garalde / Transitional | 书写血缘、编辑感、时间感或庄重感 | 最细笔画、横画灰度、低分辨率与吸墨；并非天然适合长文 |
| 黑体、拉丁 Grotesque | 中性、系统、当代或信息效率 | 字面与字重可能同样强势；“默认无衬线”若没有内容依据，容易趋同 |
| 仿宋 / 楷、Humanist | 手写血缘、人文、亲切或导视友好 | 字重档位、混排骨架、不同字号下的灰度与识别 |
| Didone、高对比展示字体 | 精细、时尚、戏剧性 | 小字与反白断画、屏幕渲染、印刷增益 |
| 圆体、Geometric | 柔性、几何秩序、建构感 | 小字符号区分、字腔、过强图形感；严肃场景不必然失效 |

**数量纪律**〔验〕：新增家族应承担现有家族无法合理承担的语言、角色或识别职责；不是以“两款”为上限。多文种、档案复刻或品牌系统可能需要更多家族，但每款的职责、混排关系与回退都应明确。

字体不能替空洞内容补性格。先让主张与文本关系成立，再让字形语气强化它。

## 四、文字角色与层级编码

先定角色及其相互关系，再定字体参数。角色由职责定义，不由大小定义。

| 角色 | 必须完成的事 | 与相邻角色的关系 | 典型失败信号 |
|---|---|---|---|
| 标题 / 主张 | 给出本页可复述的核心或入口 | 导语补足语境，不重复标题；正文兑现承诺 | 只有主题名；长标题断坏语义；与导语同重 |
| 导语 / 摘要 | 交代范围、利害或阅读前提 | 承接标题并导向正文，不变成第二标题 | 逐字复述标题；篇幅大到拖延正文 |
| 正文 | 连续解释、论证或叙述 | 段落节奏稳定；引文、数据、注释可回到主线 | 灰度斑驳、回扫错行、层级过密 |
| 引文 | 提供原声、证据或停顿 | 与正文可区分，来源与语境可追 | 只靠大引号；摘编后改变原意 |
| 数据 / 证据 | 支持比较、核验与结论 | 单位、期间、来源紧邻；与主张建立明确关系 | 数字醒目但口径缺席；小数与单位断开 |
| 标签 / 导航 | 标识类别、位置、入口和状态 | 稳定可预测，不与内容争焦点 | 样式比正文更响；同层命名不一致 |
| 注释 / 图注 / 来源 | 提供限定、出处和补充 | 靠近所注释对象，可定位且可读 | 过远、过淡或因“次要”而不可读 |

为复杂项目只记录会复用的角色契约：**语义职责、字体与真实字重、回退、目标媒介下的尺度、行距/段距、断行规则、允许变化与验收样例**。角色之间可用相同字号而不同位置，也可用不同字号而同字体；关键是关系可辨，而非维护一张庞大字级表。

**层级编码及代价**：

| 手段 | 适用收益 | 失效与副作用 |
|---|---|---|
| 字号 / 尺度 | 远距与跨媒介较直接 | 耗空间；长标题更易溢出和产生坏断行 |
| 字重 / 字形 | 密集环境有效，可保持文本块尺度 | 依赖真实字重与渲染；过粗粘连、过细消失 |
| 空间 / 位置 / 缩进 | 建立分组与阅读秩序，噪音低 | 过微妙则不可辨；窄屏重排后关系可能丢失 |
| 颜色 / 明度 | 可编码状态和强调 | 受对比、色觉与输出影响；关键层级不得只依赖它 |

**组合由失效风险决定**：远距或低质量输出优先空间、位置和尺度；密集界面可先用分组与位置；一种编码已清楚时不继续叠加。元素之间在哪里分配视觉重量见 `02`「层次反差」，这里负责把重量转成文字角色。

## 五、尺度关系

不存在通用比例。尺度由三个变量决定：**观看距离 × 文本长度 × 与主体的关系**。

- **可辨台阶**〔验〕：两处文字的字号差太小时，读者不会读成两个层级，只会读成“排得不整齐”。这个“太小”的临界随字体、字重、观看距离和目标尺寸变化——同字号下，字面大的字体看起来更大；投影距离下，同样的差值会消失。**验证方法**：把候选字号并排渲染，缩到目标尺寸（投影按后排视角、手机按实机宽度），眯眼判断能否一眼分出两级。判断不了就加大差距。

- **标题的三项决定**：观看距离（投影/手机/印刷差数倍）、标题字数（字数越多，可用字号越小）、与主体的关系（标题是否要盖过图像）。
- **大标题的成本**：字号越大，断行越难、字距越需要收紧、轮廓越容易暴露问题。标题行数增加会推迟读者进入正文的时点——需要快速进入内容的页面，先用文案解决，不要靠缩小字号硬塞。
- **极小字号**：注释与元数据可以很小，但必须在目标距离可读〔硬〕。投影与远距离场景里的极小字号是无效设计，不是精致。

## 六、行长、行距、段距

- **行长同时按实际宽度、可见字符与阅读行为判断。** 字数便于比较同一字体与语言，毫米/像素便于跨媒介落地，但任何单一数值都不是通用标准。中文连续正文行长增加时，回到下一行开头的搜索成本上升；西文还受词长、空格与连字符影响。用真实文本检查错行、重读、回扫与理解，不拿“每行固定字数”替代测试。
- 字体字面、标点密度、读者语言熟练度、行距、观看距离与媒介都会移动舒适范围。移动端不必然更短：大屏手机、横屏与分栏仍需按实际版心重判。
- **行距与行长联动。** 行长增加，行距通常要跟着增加，否则回扫会错行。行距同时是密度旋钮：信息型收紧、文学型放松。但行距不能补偿坏断行——断行错了，加行距只会让错误更明显。
- **段距与首行缩进通常二选一，但不是绝对。** 缩进是传统中文（及日文）的段落标记，段距是现代与西文的做法。选择的依据是**出版类型与阅读传统**：书籍正文、古籍整理、部分文学类出版物用缩进；报告、网页、演示、产品文档用段距。同一层级内不混用——这是为了避免读者数不清段落起止，不是为了遵守款式。两种同时出现是成立的，但要各自承担不同职责：缩进标记段落，段距标记区块（如原文／译文并列、正文与例证、多作者分栏）。职责一旦重叠，段落信号就失效。
- **密度由行长、行距、字号、字重、段距与文本块位置共同形成。** 调整前先明确要改善的是查找、连续阅读还是对照；不要靠固定顺序同时改动所有变量。
- **栏宽与栏距**：栏距明显小于行距的视觉重量时，读者读成“同一块”；明显大于时读成“两栏”。介于两者之间最危险——读者不知道是否该跨栏读。

## 七、断行与文本块轮廓

**断行是设计动作，不是排版软件的默认结果。**

- **中文按语义单位断**〔验〕：先标出专名、术语、否定结构、谓宾关系、数量与单位，再在语法接缝处选择断点。长标题优先决定“每行说哪一层意思”，再追求轮廓；若无法兼顾，先改文案或文本块。手动换行只适用于受控输出，响应式网页要用容器、短语分组与可用的换行控制共同处理。
- **多行标题检查**：逐行能否独立读出语义、行尾是否留下弱词或开括号、行首是否出现闭标点、各行视觉重量是否支持阅读顺序、末行是否只剩无意的孤字/短词。末行长于首行、短词独行或居中都不是天然错误；语义与轮廓无依据时才失败。
- **避头尾（禁则）**〔硬〕：按目标语言与出版规范保持标点及数量单位的合法关系。中文通常避免闭标点、闭引号/括号、百分号与紧密关联的单位落到行首，避免开引号/括号留在行尾；具体字符集、例外与挤压方式由所用中文排印规范决定。不同引擎支持不同，必须检查最终产物。
- **文本块轮廓**〔验〕：检查孤字、意外短末行、连续不良断点与边缘凹凸，不为追求几何整齐牺牲语义。正文更重视连续阅读，标题更重视语义分组与远距轮廓。
- **常见标题轮廓**（不是穷举）：

| 轮廓 | 效果 | 何时用 |
|---|---|---|
| 满宽齐左 | 稳重、信息型，靠内容本身的力量 | 标题短、版面需要一个稳定的顶边 |
| 阶梯／跌级（逐行渐短） | 形成一条向下的坡，把视线送到正文 | 标题较长，需要垂直推进 |
| 短行悬置（末词单独成行并拉开） | 制造停顿与强调 | 标题极短，且有一个词值得被单独看 |
| 齐右／居中 | 仪式感、对称、碑刻感 | 标题短、版面本身对称，或封面/章节页 |

- **悬挂标点与光学边距**〔境〕：引号、括号、句号与连字符可能在齐行边缘造成视觉凹口；是否外挂取决于语言规范、字体标点宽度、对齐方式与媒介。检查光学边缘是否稳定，不把“所有标点一律外挂”当规则；浏览器、Office 与出版软件能力不同，不能用伪元素造成复制/朗读顺序错误。
- **标题轮廓服务语义**：倒三角、方块、单行或短行悬置都会改变语气与阅读停顿。先用真实标题决定语义分组，再调整字数、栏宽或轮廓；不能只靠负字距把长标题挤进预定形状。

### 断行示例

标题“生成式 AI 基础设施正在进入回报验证期”不应把“生成式 AI”或“回报验证”拆到两行。优先按“生成式 AI 基础设施 / 正在进入回报验证期”组织语义，形成两行等重的块；若实际字体与栏宽导致溢出，先调整文本块或精简文案，不靠任意断词解决。若改成“基础设施进入回报验证期”，则可用单行满宽，把“生成式 AI”降为导语——改文案常常比调字号更有效。

## 八、中西文混排

- **字号匹配的实质**：CJK 与拉丁字体的字面率、x-height、大写高、升降部和字身框差异很大，同字号不一定视觉等大。比较实际墨迹高度、整行灰度与笔画重量，不套固定 em 比例；可微调西文名义字号，或换用更匹配的家族。
- **基线与行框分开校准**：CJK 表意字框、拉丁基线与软件行框不是同一概念。先检查中文中心与拉丁 x-height/大写高是否协调，再看共同基线、上下标和行内图标；最后用含最深升降部的真实混排段落检查行距。不能仅凭字体参数推断视觉平齐。
- **字体回退顺序**：CSS 等按字符回退时，字体列表顺序决定谁接管拉丁、数字、标点与符号，不只是“西文在前”。逐类核验覆盖和字形来源；设计软件则检查显式混排设置与导出后的实际嵌入。可变字体、字重映射与合成字形也要在目标引擎检查。
- **西文与中文之间的间隙**：不是一个空格的问题，而是一个视觉间隙。太小会粘连，太大像断句。按字体与字号判断，不写死是否插入空格。
- **标点与数字**：按语言上下文、出版规范与字符语义选择全角/半角，不在中文句子里误用英文句点，也不为“统一”改掉西文原文。全角标点可能被两端对齐引擎挤压；数字字形与宽度也需全篇一致，最终以真实输出为准。
- **斜体**：多数中文家族没有独立设计的斜体，机械倾斜会破坏笔画与字腔。强调优先用字重、着重号、位置或颜色；若字体提供专门设计的斜体，可在真实文本中验证后使用。

## 九、数字、表格与注释

- **等宽数字（tabular）**用于需要纵向对齐的表格与多行数据；**比例数字**用于正文与标题（字距更匀）。先验证字体是否真的提供两套——不少字体把小写数字写死为一种。
- 小数点、千分位、正负号、百分号、单位位置应全篇一致。数值与单位作为语义组处理，用目标引擎认可的不断开机制防止孤单位、孤百分号或负号与数值分离；中文“%”、拉丁 `%`、℃、°、上下标与复合单位按语境和规范处理，不机械插空格。
- **大数字的排版**：在不改变精度的前提下用单位解决数量级。被放大的数字应让单位、期间、样本与口径可辨；单位通常退居次级并紧邻数值，但具体尺度由远距识别与整体层级决定。
- 数字对齐按任务选：比较大小通常右对齐或按小数点；编号、代码与标识符可对齐字符位置或左对齐。不要为了小数点对齐破坏位数、单位和精度的语义。
- 表头、单位、来源、注释应与数据建立明确关系，不能因缩小而失去可读性。来源与口径属于正文的组成部分，不是可省略的装饰。
- 上标、脚注、交叉引用在最终格式中仍需可读、可定位；注释编号系统全篇一致。

## 十、排印肌理

排一页文字，眯眼看应当是**均匀的灰**。出现以下现象说明断行或对齐有问题：

- **白斑**：多行短行叠加形成的亮块。
- **暗斑**：某些行被挤压，或字重不一致形成的深块。
- **河流**（rivers）：词间距连成的白色竖向通道，多见于两端对齐的窄栏。
- **斜线纹理**：连续多行以连字符结尾，形成一条可见斜线。

**两端对齐的策略**：中文两端对齐相对安全（可微调字距与标点），但需控制标点挤压与字距累计——一味拉字距会让行内出现疏密不匀。拉丁窄栏 + 长词 + 无连字符会产生河流，此时改用左对齐或允许连字符。连字符是拉丁文的必要工具，但需限制连续连字符行数。

## 十一、编辑性排印元素

这些元素决定作品“像不像出版物”，而不是“像不像幻灯片”。

| 元素 | 职责 | 使用条件 |
|---|---|---|
| 首字（drop cap / raised cap） | 标记文章起点、建立入口 | 有明确的文章开端且值得强调；与首行缩进、段距和后续行对齐共同校准，不因“出版感”强加 |
| 引文（pull quote） | 让快速翻阅的人抓到论点或原声 | 忠于原文与语境；数量由跨页职责决定，若与标题、正文争夺同一入口则删减或降级 |
| 图注 | 说明图像是什么、谁拍的、何时、有何限制 | 与图绑定且可定位；长度、宽度和尺度按阅读任务校准，通常退居正文之后但仍须可读 |
| 旁注（marginalia） | 提供不打断主线的补充 | 外边距真的够宽；不够宽时它只是挤压 |
| 页眉 / 页脚 / 页码 | 导航与定位 | 位置、字号、对齐全篇一致；不与内容争注意力 |
| 目录 | 信息架构的自我说明 | 编号、引导线、页码对齐是基本功；条目文字应反映真实章节职责 |
| 分栏标题（running head） | 让读者知道自己处在哪一节 | 需要真实的章节结构，不能为装饰而设 |

## 十二、屏幕与移动端排印

屏幕排印的失败与印刷不同：它不发生在纸上，发生在**字体加载、布局重排和像素渲染**这三个环节。

- **加载策略**：按目标网络与设备检查 FOIT、FOUT、阻塞时间与替换后的重排。关键文案不得因 Web 字体未加载而消失〔硬〕；选择 `font-display`、预加载与子集化时，同时检查缓存、跨域、字符覆盖和布局位移，不能只看字体文件是否请求成功。
- **回退度量**：回退字体与目标字体的字宽、x-height、升降部和默认行框不同，会改变断行与容器高度。可用度量覆盖、尺寸调整或更兼容的回退减少跳变，但需在字体未加载、慢加载与已加载三种状态实测；数值匹配不等于灰度匹配。
- **文本扩张与替换**：不同语言、系统字体、字体版本和用户翻译会改变长度。布局必须容纳实际交付中的最长合理文案与动态内容，不能用占位文字估长度〔硬〕；无法预知上限时，定义换行、截断、展开或滚动策略及其信息损失。
- **用户字号与缩放**：系统字号、浏览器文字缩放和页面缩放是不同条件。在支持放大的界面检查较大用户设置；固定高度、固定行数与绝对定位最容易截断。不得为守住设计稿禁止用户缩放〔硬〕。
- **像素与极性**：细画、hinting、抗锯齿、像素密度、暗底亮字的光晕感与屏幕亮度都会改变视觉字重。按实际设备和输出比例检查，不假定 1x/2x 截图能代表所有屏幕。
- **动态尺度与重排**：流式字号只改变尺度，不自动解决行长、断行和触控布局。检查最短/最长标题、窄屏、横屏、分屏与字体回退后的语义分组；不能用缩小后的桌面画布代替真实宽度。

## 十三、故障与优先处理

| 故障 | 先查 | 优先动作 | 不要先做 |
|---|---|---|---|
| 标题不突出 | 文案是否明确、占幅是否足够、位置是否有效 | 精简主张，调整文本块与位置，再调字号字重 | 加粗、加下划线、加色块 |
| 标题像一堵墙 | 语义是否过长、断行是否任意 | 改写或拆分文案，设计断行与轮廓 | 缩小字号塞进一行 |
| 正文难读 | 行长、密度、对比、行距、阅读距离 | 重分组，调栏宽与文本块，再微调字级 | 换一款“更好看”的字体 |
| 中文标题断行生硬 | 语义单位、专名、标点、标题形状 | 先改文案或栏宽，再控制断行 | 手动插入空格撑开 |
| 中西文混排参差 | 字面高度、基线、字体回退、字重映射 | 在实际渲染环境校准视觉字面高度与基线 | 只按名义字号对齐 |
| 数字列不齐或难比较 | 位数、精度、单位位置、数字宽度 | 统一格式、精度、单位与对齐方式 | 手动加空格凑齐 |
| 页面充满近似字号 | 文字角色是否真的不同 | 合并无实质差异的层级，用空间与位置建立关系 | 再发明两个新字号 |
| 整页读起来“毛” | 断行、词距、行距是否互相冲突 | 先修断行，再调词距，最后动行距 | 全篇拉开字距 |
| 文字在图上读不清 | 图像最亮/最暗区域的实际对比 | 改裁切、改文字位置、局部压暗或提亮 | 给文字加半透明底板 |

文字压图时的对比判定与取样方法，见 `04`「裁切与文字避让」与 `07`「证据口径」。

## 十四、渲染验证

字体名称、源文件正常与工具导出成功都不能证明最终排印成立〔硬〕。先导出真实产物，再按目标尺寸、距离与环境查看，最后回源文件修正；媒体完整检查见 `06`。

| 环境 | 必看的排印差异 | 合格证据 |
|---|---|---|
| 桌面 / 移动浏览器 | 字体加载前后、回退度量、最长文案、文字缩放、系统字号、不同排版引擎 | 目标浏览器与宽度的加载状态及最终状态；异常截图或检查记录 |
| PPT / Office | 目标系统是否缺字、真实字重映射、文本框 autofit、行距与标点禁则变化 | 在实际播放环境渲染，检查完整文稿与长文案页 |
| PDF / 电子书 | 字体嵌入/子集、复制与检索、字符编码、分页、阅读器重排 | 导出后预检并在目标阅读器查看；印刷 PDF 另做印前检查 |
| 印刷 | 最细笔画、反白、油墨增益、纸张与 RIP、字重实际成像 | 印前报告加必要的数码样/上机样；源文件截图不算 |

通用崩坏包括：字体未嵌入或被替换、字重合成、生僻字与符号回退、避头尾失效、两端对齐挤压不同、文本框重排、字体加载跳动、复制乱码。检查应覆盖**正文长段、最长标题、中西文混排、特殊字符、数字表格、注释与图上文字**，不是只看一张标题页。

没有实际检查时，明确写出未验证的环境与风险；不得用字体选单、设计画布或文件可打开代替渲染结果。
