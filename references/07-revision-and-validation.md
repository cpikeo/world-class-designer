# 根因诊断、修正、验证与停止

本文件拥有：修改前判断、优先级、最小修正协议、整体视觉一致性诊断与归因、证据层级、硬门槛与可观察证据、证据口径、复跑与独立评估、停止与回退。各媒介的不可省证据见 `06`；交付状态用语见 `06`「通用交付契约」。

## 一、修改前：四项必要判断

1. **可观察问题**：具体哪里失效？“还不够高级”“再大气一点”不是缺陷描述。合格的描述是“缩略图上结论与四条证据同等显眼”。
2. **根因层级**：事实/目标、概念、内容与证据、信息结构、版面与阅读路径、排印/色彩/图像、执行/渲染——问题落在哪一层？
3. **最小有效干预**：哪个改动最可能解决它？只有相互依赖的改动才一起执行。
4. **预期证据**：改后应出现什么可观察变化，同时哪些既有成果需要保持？

无法说明问题或预期证据时，不要为了“继续优化”而改动。先观察真实产物、补充事实，或保留现状。

**根因层与典型误修**：

| 根因层 | 典型症状 | 常见误修（只会加重问题） |
|---|---|---|
| 事实与目标 | 主张无处落脚、结论超出证据 | 加大视觉冲击 |
| 概念 | 换成任何同类项目都成立 | 换配色、加装饰、换字体 |
| 内容与证据 | 论证有缺口、缺少关键数据 | 排版更紧凑，掩盖缺口 |
| 信息结构 | 层级不成立、分组错误 | 缩小字号、增加栏数 |
| 版面与阅读路径 | 无焦点、无序、视线散 | 微调间距与对齐 |
| 排印 / 色彩 / 图像 | 难读、脏、色相冲突、图不承载信息 | 整体推翻重做 |
| 执行 / 渲染 | 溢出、字体替换、裁切错误、导出异常 | 当成设计问题重排 |

**改错层是最常见的浪费**：在排印层反复微调一个结构问题，永远调不好，还会破坏已经成立的部分。

## 二、优先级

- **P0｜交付阻断**：事实错误、误导、关键内容缺失、严重不可读、文件不可用。
- **P1｜方向与结构**：目标、主张、概念、叙事、信息层级、版面结构或关键关系不成立；跨区块与跨页的连续性断裂、结构变化无内容依据。
- **P2｜表达质量**：构图、空间、排印、色彩、图像、材质、节奏、一致性的具体问题。
- **P3｜工艺细节**：细小间距、线宽、非关键对齐、装饰；只有收益明显大于成本与副作用时处理。

先修高优先级，不用 P2/P3 精修掩盖 P0/P1 失败。修完高优先级后，复查其影响范围内的低优先级决定是否仍成立——改一处结构，通常会使若干细节决定失效。

## 三、最小修正协议

用最短方式记录：**问题 → 根因 → 改动 → 预期变化 → 实际结果。** 复杂修订可增加“保持项”，防止修一个问题时破坏另一个已验证成果。

执行后在相同目标、素材、尺寸与渲染条件下比较，判断改善、相当、退步或仍不确定，并检查副作用。

- **无改善**：回退或换用有依据的方案，不在失败改动上无限叠补丁。
- **局部错误**：优先局部修复，不重做无关部分。
- **上游错误**：回到概念、内容或结构层，不靠装饰修补。
- **新证据出现**：只重审受影响的决定，保留其他已验证部分。
- **多改动难以判断贡献时**：减少同时变化的变量，除非它们不可分割。
- **共用系统被修改时**：抽查未直接修改但继承该系统的页面、状态或镜头。

**变量纪律**：一次只改一个主导变量（结构、字体、色彩、图像之一），除非它们互为前提。同时换字体、换色、改版式，得到的是一个“看起来不同”的结果，学不到任何东西。

## 四、整体视觉一致性诊断

局部修正协议解决“这一处坏了”。另一类问题不落在任何一处：每块单独看都成立，整体读起来像拼接。它需要单独一轮诊断，位置在单块检查之后、细节修整之前。

### 六层检查序

| 层 | 问什么 | 通过判据 | 不通过时回到 |
|---|---|---|---|
| **1 局部成立** | 每块是否服务一个明确的内容职责 | 能用一句关系句命名（`02`「从内容到结构」第 6 步） | 内容取舍与结构（`01`、`02`） |
| **2 区块协调** | 相邻区块是否继承至少一项主要视觉关系 | 能说出继承项、变化点与驱动源 | `02`「页面连续性与视觉继承」 |
| **3 页面连续** | 整页三个视图（缩略／边缘／色带）是否像一个作品 | 三项都通过 | `02` 同上；`04`「跨页面与跨媒介的色彩连续性」 |
| **4 品牌识别** | 去掉文字与标志，是否仍属于同一品牌 | 八层中至少两三层可辨（`05`「从核心概念到识别系统」） | 品牌层：定位、常量、母题 |
| **5 跨页面一致** | 常量稳定、变量有依据 | 抽查三处异常处理都能说出驱动源 | `05`「识别常量、变量」 |
| **6 跨媒介转译** | 共享的是设计逻辑，不是版式 | 换一种信息容量后常量仍可执行 | `06`「跨媒介转译」 |

不要跳层：第 2 层失败时去修第 4 层（换品牌色、换主字体），拼接感不会消失，只会更明显。

### 去文字测试

把交付物缩到文字不可读，或模糊到无法辨字，只看色块、边界、主体、尺度与空间。四问：

1. 还看得出主次吗？如果主次全靠文字大小支撑，版面的权力分配其实没有做。
2. 背景场是连续的，还是在某个位置突然换了世界？
3. 内容块的边界逻辑是一种，还是两三种混用？
4. 相邻区域属于同一件作品吗？

出现否定答案时，先归因，再决定修不修——不是所有断裂都要消除。

### 四种归因与对应修正

| 归因 | 现象 | 最小修正 | 不要做 |
|---|---|---|---|
| **同一场景中的内容延伸** | 本应连读，却做成了独立模块 | 合并背景场、共享一条锚线、把次级信息改为嵌入 | 加过渡色块或渐变“缝合” |
| **真实存在的对峙与对照** | 本应对峙，却挤在同一场里互相削弱 | 明确分离、合理等权、保留一条共享锚 | 靠压低对比强行统一 |
| **必要的叙事转折** | 转折突兀，读者没有准备 | 补前置信号（尺度、密度、色温、边界的渐进），保留转折本身 | 取消转折，退回同一版式 |
| **被误做成了另一个模块** | 没有内容依据，却给了独立底色、容器或边界 | 取消容器与异质边界，回到内容关系 | 调圆角、阴影、间距掩盖 |

第四种最容易发生：因为“这块内容看起来重要”就给它一个卡片或深色块——依据是重要性感受，不是内容判断。

### 修正顺序

**内容关系与结构 → 背景场与图像 → 色彩职责与面积 → 字体角色与尺度 → 工艺细节。**

倒过来做（先改圆角、阴影、描边、间距）只会让断裂更精致，不会让它消失。这与「优先级」的 P0–P3 一致：连续性断裂属于 P1，圆角与阴影属于 P3。

### 整体证据与停止

整体视图的证据句同样要带范围：「已检查 16 页按顺序的缩略图带，及第 3–9 页相邻对照，观察到第 6 页整块深底卡片与前后两页无继承依据；未检查打印输出」。不要写“整体协调性良好”。

停止条件：每个区块都能说出继承项与变化依据，缩略图带上不再出现无依据的跳变，且继续统一的收益低于它带来的单调风险。**把所有区块统一成一种背景与一种容器，不是通过，是把作品做成了模板。**

连续性不作为硬门槛：它不是可核验的二元条件，而是判断。把它伪装成“必须通过”的检查项，只会让设计去迎合规则，而不是服务内容。

## 五、证据层级与验证深度

证据层级回答“看到了什么”，不是由弱到强的审美分：

| 证据类型 | 能证明什么 | 不能顶替什么 |
|---|---|---|
| 源文件检查 | 内容、样式、资源、结构在源文件中如何定义 | 导出、字体替换、分页、响应式与真实播放 |
| 真实渲染 / 导出产物 | 某个渲染器实际生成的外观、文件与可观察错误 | 所有目标环境；真实交互、印刷与完整动态 |
| 目标环境检查 | 声明的设备、浏览器、播放器、投影、阅读器或打样中的结果 | 未测设备、用户是否理解、长期稳定性 |
| 用户体验检查 | 指定参与者在任务中的完成、误读、回扫或操作问题 | 全体用户统计结论；事实正确性与技术合规需另证 |
| 独立对照评估 | 固定输入与判据下，版本/模型/方案在样本上的相对结果 | 超出样本的普遍优越性或单次成功后的稳定声明 |

按风险选择深度：微任务检查受影响的真实结果；复杂或正式交付检查真实产物与目标环境；声称提升、优越性或稳定性才需要对照评估。先固定任务、输入、媒介与判据，再比较基线与改后结果；单次成功不能证明稳定。

检查器通过、格式合法、文件可打开、截图生成和工具调用成功都只是对应步骤的证据，不能代替设计判断。

## 六、硬门槛与可观察证据

验证分两轨，不要混用。

### 硬门槛：是/否，不可加权

| 门槛 | 判定方式 | 不通过时 |
|---|---|---|
| 事实与口径 | 来源可核；单位、期间、基线、样本前后一致；关键值可复算；图像属性不误导 | 停止交付，先修事实 |
| 可读性与必要可达性 | 在声明的目标尺寸/距离，必要文字与操作可辨；适用对比标准满足；主任务不被输入方式阻断 | 停止交付或限制交付范围 |
| 完整性 | 任务所需内容、限定、来源、图注、导航与交付文件在位 | 停止交付 |
| 执行 | 无影响内容/操作的溢出、遮挡、乱码、未接受字体替换、裁切吃字、占位符或资源缺失 | 停止交付 |

硬门槛只判断可核验的交付条件，不把“是否有高级感”“识别常量是否足够独特”等设计判断伪装成二元测量。适用门槛未检查时状态是**未验证**，不是默认通过；若某门槛不适用于该任务，写明理由。

### 可观察证据：描述性，必须带范围

证据用来回答“它是否变好了”，不回答“它有多好”。合格的证据句形：

> 已检查〔范围〕，观察到〔现象〕，未检查〔范围〕。

例：「已检查 16 页在 1920×1080 投影下的渲染，观察到第 7 页图注在与深色背景交界处对比不足；未检查打印输出与后排实际观看。」

不合格的证据句：「整体效果提升明显，设计质量达到 90 分。」——既无范围，也无现象，且把审美包装成了测量。

### 不评分

不做五分制、百分制、加权总分，也不给“设计质量分”。原因是：把事实正确性、可读性、构图、风格偏好加权求和，得到的数字不对应任何可观察对象，只会让未经证明的判断显得像结论。需要比较两个方案时，用逐项门槛通过情况与证据描述，不用分数。

## 七、证据口径

**口径错误的“实测”比不测更坏——它会为错误结论背书。**

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 用整个文本框取样算对比度 | 把空白和背景都算成“文字底色” | 只取文字真正占据的区域，并取最坏处 |
| 假设背景图恒铺满整页 | 实际裁切、留白、蒙版都会改变底层 | 按实际 `cover/contain` 落位后合成再测 |
| 用平均亮度判断可读性 | 平均值掩盖亮暗交界处的失效 | 分别检查最亮与最暗区域 |
| 在 100% 缩放判断投影可读性 | 会议室距离下层级会消失 | 按目标距离等效缩小后再看 |
| 只看单页代表全稿 | 分页、跨页、状态变化会引入新故障 | 抽查同系统未直接修改的页面 |
| 用缩略图判断细节 | 细节问题在缩略图上不可见 | 缩略图看关系，100% 看执行 |
| 用一次去饱和截图代替全部色彩证据 | 忽略彩稿关系、实际对比、色觉类型与输出介质 | 按 `04`「色彩职责、可读性与输出校准」分层检查，灰度只作辅助 |

报告中写清取样方式、工具/环境、版本（影响结果时）、检查对象与范围。未声明的“已检查”不算证据。

### 证据最小矩阵

下表用于选择证据，不要求每个项目全做；媒介细目以 `06` 为准。

| 对象 | 至少需要的真实证据 | 不能算作替代 |
|---|---|---|
| 字体与排印 | 目标引擎中的真实文本、最长标题、特殊字符、字重与回退；按媒介查嵌入/加载/缩放 | 字体选单、家族宣传、源文件截图 |
| 图片与摄影 | 实际输出的主体、结构、光线、材质、边缘、来源属性及目标尺寸；组图另看接触表 | 提示词、素材缩略图、生成成功 |
| 色彩 | 实际相邻色与图像背景、文字/非文本适用对比、灰度或色觉辅助检查、目标输出 | 孤立色板、OKLCH 数值、平均亮度 |
| 品牌与叙事 | 跨页/跨触点真实产物中的常量、变量、信息增量与替换主题表现 | 概念板、品牌形容词、单页美观 |
| 网页 / 产品 | 目标浏览器与宽度、关键交互状态、键盘主任务、声明的实机/网络/辅助技术范围 | 静态 mockup、单次自动审计 |
| PPT | 完整渲染与全稿节奏、关键页目标播放环境、字体/媒体/动画后状态 | 编辑画布、单页截图、静态 PDF 代全部 |
| 出版 / 印刷 | 导出 PDF、跨页与印前预检；按生产风险增加数码样/上机样 | 阅读器截图代印刷、单页代跨页 |
| 视频 / 动效 | 编码后完整播放、连续性、字幕、音画同步及必要替代路径 | 关键帧、静帧拼图、时间线预览 |
| 整体连续性 | 整页长截图或全稿缩略图带、相邻对照、去文字视图 | 单页通过、区块检查通过、概念板 |

## 八、复跑与独立评估

需要声称“跨模型、跨任务或跨运行稳定”时，使用独立评估，而不是根据单次体验推断：

- **冻结任务包**：固定输入事实、原始素材、约束、目标媒介与验收判据；只改变被评估的技能版本或模型条件。任务覆盖不同媒介、复杂度、长文案、异常输入与真实产物，而非只选成功案例。
- **在干净上下文中独立复跑**，避免上一轮的候选与结论成为下一轮提示；记录模型、运行条件、失败与缺失产物，不只保留成功样本。
- **预先明确判据**：事实与必要信息是否保留、P0/P1 是否识别、根因是否正确、产物是否可交付、验收范围是否覆盖主要风险。概念与构图允许多种有效答案，不把不同于参考答案直接判为失败。
- **跨模型使用同一任务包与判据**，按事实错误、方向错误、执行错误、漏验、过度修改和工具误报分类记录，而不是只比较总分。
- **需要盲测时隐藏版本与模型身份**，随机化方案呈现顺序，让独立评价者按同一现象判据检查；事实/任务正确性与审美偏好分开报告，并保留分歧。
- **结论不超出样本**：报告任务数、产物覆盖、失败与限制。单次成功、单一模型或单一任务不能支持“稳定提升”；没有跨模型结果就不能声称跨模型稳定。

评估集、盲测记录与对照样本留在独立开发工作区，不进入正式运行包。没有实际结果时只能提供协议，不能声称评估已执行或通过。

## 九、状态声明的纪律

状态用语的定义见 `06`「通用交付契约」，本文件不重复定义。以下只约束**如何声明**：

- 状态必须带范围：不是“已检查”，而是“已检查全 16 页的投影尺寸渲染，未检查打印色”。无范围的声明等于无声明。
- 不得跨层顶替：提示词质量不代图像质量，单页检查不代全稿验收，静帧检查不代动态验证，源文件正常不代导出正常。
- 不得用工具成功代设计有效：文件生成、检查器通过、格式合法都只是生产成功，不是设计成立。
- 报告只写影响决策的证据、未解决风险与实际限制，不写“已全面优化”这类无信息量的结论。

## 十、停止与回退

当首要目标实现、核心关系易于理解、必要事实完整、主要执行故障已处理，且继续修改的预期收益低于破坏既有成果的风险时停止。

没有改善就回退到最近的有效版本。仍可调整颜色、字体或间距，不代表必须继续修改；**终点是任务有效、结果可信，不是每个元素都更显眼。**

停止前最后自问三句：读者能复述主张吗？证据够支撑到那个程度吗？还有哪一处是我在修饰而不是在解决？

## 十一、短案例：执行层故障被当成设计层

现象：一份导出的 PDF 被反馈“文字发虚、层级出不来”。

- **错误修正**：回到设计文件，把标题加粗、字号加大、换成更重的字体。结果字更糊，层级依旧，且原本清晰的部分也被破坏了。
- **根因**：字体未嵌入，导出时字重被替换，加粗由渲染器合成的“伪粗体”提供——属于**执行 / 渲染层**，不是排印层。
- **最小干预**：嵌入字体、改用真实存在的字重、重新导出；不改字号与层级决定。
- **对照条件**：同一内容、同一尺寸、同一导出设置，只改字体嵌入与字重来源。
- **通过证据**：放大到 100% 后笔画边缘干净，无粘连；缩到目标尺寸后三级层级仍可分辨；未引入新的溢出或断行变化。
- **保持项**：原有字号关系、行长、断行与页面结构不变。
- **教训**：症状出现在“字”上，不等于根因在“字”上。先定位层级，再动手。
