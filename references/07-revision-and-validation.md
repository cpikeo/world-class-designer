# 根因诊断、修正、验证与停止

本文件拥有：修改前判断、优先级、最小修正协议、跨领域冲突裁决、六层一致性归因、三层验证、硬门槛、证据口径、评估协议、停止与回退。各媒介的不可省证据见 `06`；交付状态用语见 `06`「通用交付契约」。

## 一、修改前：四项必要判断

1. **可观察问题**：具体哪里失效？“还不够高级”“再大气一点”不是缺陷描述。合格的描述是“缩略图上结论与四条证据同等显眼”。
2. **根因层级**：事实/目标、概念、内容与证据、信息结构、版面与阅读路径、排印/色彩/图像、执行/渲染——问题落在哪一层？
3. **最小有效干预**：哪个改动最可能解决它？只有相互依赖的改动才一起执行。
4. **预期证据**：改后应出现什么可观察变化，同时哪些既有成果需要保持？

无法说明问题或预期证据时，不要为了“继续优化”而改动。先观察真实产物、补充事实，或保留现状。

**根因层与典型误修**：

| 根因层 | 典型症状 | 常见误修（只会加重问题） |
|---|---|---|
| 事实与目标 | 主张无处落脚、结论超出证据 | 加大视觉冲击 |
| 概念 | 换成任何同类项目都成立 | 换配色、加装饰、换字体 |
| 内容与证据 | 论证有缺口、缺少关键数据 | 排版更紧凑，掩盖缺口 |
| 信息结构 | 层级不成立、分组错误 | 缩小字号、增加栏数 |
| 版面与阅读路径 | 无焦点、无序、视线散 | 微调间距与对齐 |
| 排印 / 色彩 / 图像 | 难读、脏、色相冲突、图不承载信息 | 整体推翻重做 |
| 执行 / 渲染 | 溢出、字体替换、裁切错误、导出异常 | 当成设计问题重排 |

**改错层是最常见的浪费**：在排印层反复微调一个结构问题，永远调不好，还会破坏已经成立的部分。

## 二、优先级

- **P0｜交付阻断**：事实错误、误导、关键内容缺失、严重不可读、文件不可用。
- **P1｜方向与结构**：目标、主张、概念、叙事、信息层级、版面结构或关键关系不成立；跨区块与跨页的连续性断裂、结构变化无内容依据。
- **P2｜表达质量**：构图、空间、排印、色彩、图像、材质、节奏、一致性的具体问题。
- **P3｜工艺细节**：细小间距、线宽、非关键对齐、装饰；只有收益明显大于成本与副作用时处理。

先修高优先级，不用 P2/P3 精修掩盖 P0/P1 失败。修完高优先级后，复查其影响范围内的低优先级决定是否仍成立——改一处结构，通常会使若干细节决定失效。

## 三、最小修正协议

用最短方式记录：**问题 → 根因 → 改动 → 预期变化 → 实际结果。** 复杂修订可增加“保持项”，防止修一个问题时破坏另一个已验证成果。

执行后在相同目标、素材、尺寸与渲染条件下比较，判断改善、相当、退步或仍不确定，并检查副作用。

- **无改善**：回退或换用有依据的方案，不在失败改动上无限叠补丁。
- **局部错误**：优先局部修复，不重做无关部分。
- **上游错误**：回到概念、内容或结构层，不靠装饰修补。
- **新证据出现**：只重审受影响的决定，保留其他已验证部分。
- **共用系统被修改时**：抽查未直接修改但继承该系统的页面、状态或镜头。

**变量纪律**：一次只改一个主导变量（结构、字体、色彩、图像之一），除非它们互为前提。同时换字体、换色、改版式，得到的是一个“看起来不同”的结果，学不到任何东西。

## 四、整体视觉一致性诊断

局部修正协议解决“这一处坏了”。另一类问题不落在任何一处：每块单独看都成立，整体读起来像拼接。它需要单独一轮诊断，位置在单块检查之后、细节修整之前。

### 六层检查序

| 层 | 问什么 | 通过判据 | 不通过时回到 |
|---|---|---|---|
| **1 局部成立** | 每块是否服务一个明确的内容职责 | 能用一句关系句命名（`02`「从内容到结构」第 6 步） | 内容取舍与结构（`01`、`02`） |
| **2 区块协调** | 相邻区块是否继承至少一项主要视觉关系 | 能说出继承项、变化点与驱动源 | `02`「页面连续性与视觉继承」 |
| **3 页面连续** | 四个视图（缩小／序列带／边缘图／相邻对照）是否像一个作品 | 四项都通过 | `02`「整页检查：四个视图」；`04`「跨页面与跨媒介的色彩连续性」 |
| **4 品牌识别** | 去掉文字与标志，是否仍属于同一品牌 | 八层中至少两三层可辨（`05`「从核心概念到识别系统」） | 品牌层：定位、常量、母题 |
| **5 跨页面一致** | 常量稳定、变量有依据 | 抽查三处异常处理都能说出驱动源 | `05`「识别常量、变量与差异化审查」 |
| **6 跨媒介转译** | 共享的是设计逻辑，不是版式 | 换一种信息容量后常量仍可执行 | `06`「跨媒介转译」 |

不要跳层：第 2 层失败时去修第 4 层（换品牌色、换主字体），拼接感不会消失，只会更明显。

### 四种归因与对应修正

`02`「先判关系，再选接合」问的是“这两块本来是什么关系”（动手前）；本节问“已经出现的断裂属于哪一种”（看见之后）。

| 归因 | 现象 | 最小修正 | 不要做 |
|---|---|---|---|
| **同一场景中的内容延伸** | 本应连读，却做成了独立模块 | 合并背景场、共享一条锚线、把次级信息改为嵌入 | 加过渡色块或渐变“缝合” |
| **真实存在的对峙与对照** | 本应对峙，却挤在同一场里互相削弱 | 明确分离、合理等权、保留一条共享锚 | 靠压低对比强行统一 |
| **必要的叙事转折** | 转折突兀，读者没有准备 | 补前置信号（尺度、密度、色温、边界的渐进），保留转折本身 | 取消转折，退回同一版式 |
| **被误做成了另一个模块** | 没有内容依据，却给了独立底色、容器或边界 | 取消容器与异质边界，回到内容关系 | 调圆角、阴影、间距掩盖 |

第四种最容易发生：因为“这块内容看起来重要”就给它一个卡片或深色块——依据是重要性感受，不是内容判断。

### 修正顺序

修正顺序即优先级：**内容关系与结构 → 背景场与图像 → 色彩职责与面积 → 字体角色与尺度 → 工艺细节**。倒过来做只会让断裂更精致，不会让它消失（断裂属 P1，圆角与阴影属 P3）。

### 整体证据与停止

整体证据句同样带范围：「已检查 16 页缩略图带与第 3–9 页相邻对照，观察到第 6 页整块深底卡片与前后两页无继承依据；未检查打印输出」。不要写“整体协调性良好”。

停止条件：每个区块都能说出继承项与变化依据，缩略图带上不再出现无依据的跳变，且继续统一的收益低于它带来的单调风险。**把所有区块统一成一种背景与一种容器，不是通过，是把作品做成了模板。** 连续性不作为硬门槛：它是判断，不是可核验的二元条件。

## 五、跨领域冲突诊断

单领域故障回各自章节；这里只处理**两个领域各自通过、合起来不成立**的情形。它不新增判据，只规定冲突时谁让位、怎么让。

1. **先判谁承载任务结果**：读者必须读懂、比较或核验的那件事依赖哪一方，另一方让位。让位不是削弱，是换手段——改裁切、改位置、改分组、改顺序，并记录换了什么。
2. **不得用平均化解决**：调低对比、压掉一端、加罩层、统一色温、把两种语法都减半，都等于两个决定都没做完。
3. **让位后查第三方**：改构图会改变文字可读区，改色彩会改变图像的事实读法，改排印会改变节奏与断行。按「最小修正协议」复查副作用，不能只验被让位的那一方。

| 冲突 | 先判 | 动作 | 不许做 | 失败信号 |
|---|---|---|---|---|
| 构图要满幅主体 ↔ 排印要文字对比 | 文字是否必须压图（`02`「网格与自由版式」的图文穿插许可条件） | 改裁切、机位或改分区，让出一块可读区 | 加半透明底板、压暗整图、给文字描边 | 缩略图上标题仍先被读到，100% 下笔画与背景糊在一起 |
| 结构要单一焦点 ↔ 内容要并列比较 | 预期路径是否可辨（`02`「结构组合」判据 1） | 用分组、编号、尺度梯度建有序多入口 | 压掉一侧，或把两侧统一成同权重 | 读者说不出先看哪，或比较轴被拆散 |
| 品牌常量要大字重标题 ↔ 移动端行长与断行 | 该常量是关系还是样式（`05`「识别常量、变量与差异化审查」） | 改角色契约：字号关系、行数上限、断行规则 | 为守住字号允许孤字、溢出或遮挡 | 窄屏出现末行孤字、截断，或标题吃掉触控区 |
| 色彩要单一世界 ↔ 图像的事实色彩 | 这张图是否作证据（`04`「高级色彩语言」的图像与品牌色三种关系） | 改选图、裁切或顺序；必要时降级为示意并标注 | 统一压色温、加品牌滤镜 | 图仍“好看”，但已不能作为证据 |
| 叙事要转折 ↔ 连续性要继承 | 转折由哪项内容变化驱动（`02`「页面连续性与视觉继承」变化四问） | 只改一处结构变量，保留至少一项继承 | 换整套版式，或取消转折退回同构 | 相邻两页读成两个作品，或全篇没有认知变化 |
| 概念要极端尺度 ↔ 必要限定不能消失 | 被放大的是否为必要信息（`01`「约束下的降级」） | 只在非必要信息上放大；限定变小、变近、变清楚 | 删单位、口径、期间换版面 | 主张醒目但支撑不住，读者无法核验 |

第三条规则最常被跳过：让位几乎总会制造新的局部故障，只验让位方，等于用新问题换旧问题。

## 六、三层验证与证据层级

验证按三层组织，**按风险启用，不逐层全做**。微任务只碰第一层与受影响部分；复杂产物才走满三层。

| 层 | 查什么 | 机制在哪 | 何时必须做 |
|---|---|---|---|
| **第一层 硬门槛** | 事实与口径、可读性、完整性、执行 | 「硬门槛：是/否，不可加权」 | 任何交付前；不通过即停 |
| **第二层 专业视觉判断** | 字体、图像、色彩、构图、品牌识别、连续性、叙事 | 各 Reference 的判据＋「整体视觉一致性诊断」 | 常规与复杂任务；不可二元化，只用证据句 |
| **第三层 真实产物证据** | 渲染、整页、目标设备、实际输出、打样、完整播放 | 「证据口径」＋`06` 各媒介的不可省证据 | 有交付风险或要声称通过时；无环境则标未验证 |

第二层最容易被做成假精确：把“层级是否清楚”“识别是否成立”做成勾选项，等于用清单替代判断。它只能以证据句表达，且允许两版都成立而取舍不同。**验证深度由风险与影响决定，不由流程完整度决定。**

**任何交付的最小证据是三件事**，比这三件少就是没验证，比这三件多通常只是重复：**① 真实产物一份**（渲染或导出，不是画布或源文件）；**② 目标环境下的一次查看**（目标尺寸、距离或设备）；**③ 关键异常点**（最长文案、最窄宽度、最坏对比区、最大数据量、最容易假通过的那一项）。这三件不覆盖全部风险，但能证明“看过真实结果”，其余按 `06` 各媒介的不可省证据补。

第三层还要区分证据类型——下表回答“看到了什么”，不是由弱到强的审美分：

| 证据类型 | 能证明什么 | 不能顶替什么 |
|---|---|---|
| 源文件检查 | 内容、样式、资源、结构在源文件中如何定义 | 导出、字体替换、分页、响应式与真实播放 |
| 真实渲染 / 导出产物 | 某个渲染器实际生成的外观、文件与可观察错误 | 所有目标环境；真实交互、印刷与完整动态 |
| 目标环境检查 | 声明的设备、浏览器、播放器、投影或打样中的结果 | 未测设备、用户是否理解、长期稳定性 |
| 用户体验检查 | 指定参与者在任务中的完成、误读、回扫或操作问题 | 全体用户统计结论；事实正确性与技术合规需另证 |
| 独立对照评估 | 固定输入与判据下，版本/模型/方案在样本上的相对结果 | 超出样本的普遍优越性或单次成功后的稳定声明 |

先固定任务、输入、媒介与判据，再比较基线与改后结果；单次成功不能证明稳定。**检查器通过、格式合法、文件可打开、截图生成和工具调用成功都只是对应步骤的证明，不能代替设计判断。**

## 七、硬门槛与可观察证据

验证分两轨，不要混用。

### 硬门槛：是/否，不可加权

| 门槛 | 判定方式 | 不通过时 |
|---|---|---|
| 事实与口径 | 来源可核；单位、期间、基线、样本前后一致；关键值可复算；图像属性不误导 | 停止交付，先修事实 |
| 可读性与必要可达性 | 在声明的目标尺寸/距离，必要文字与操作可辨；适用对比标准满足；主任务不被输入方式阻断 | 停止交付或限制交付范围 |
| 完整性 | 任务所需内容、限定、来源、图注、导航与交付文件在位 | 停止交付 |
| 执行 | 无影响内容/操作的溢出、遮挡、乱码、未接受字体替换、裁切吃字、占位符或资源缺失 | 停止交付 |

硬门槛只判断可核验的交付条件，不把“是否有高级感”“识别常量是否足够独特”等设计判断伪装成二元测量。适用门槛未检查时状态是**未验证**〔硬〕，不是默认通过；若某门槛不适用于该任务，写明理由。

### 可观察证据：描述性，必须带范围

证据用来回答“它是否变好了”，不回答“它有多好”。合格的证据句形：

> 已检查〔范围〕，观察到〔现象〕，未检查〔范围〕。

例：「已检查 16 页在 1920×1080 投影下的渲染，观察到第 7 页图注在与深色背景交界处对比不足；未检查打印输出与后排实际观看。」

不合格：「整体效果提升明显，设计质量达到 90 分。」——既无范围，也无现象，且把审美包装成了测量。

**不评分**〔硬〕。五分制、百分制与加权总分都不对应任何可观察对象；把事实正确性、可读性、构图与风格偏好加权求和，只会让未经证明的判断显得像结论。比较两个方案时，用逐项门槛通过情况与证据描述。

## 八、证据口径

**口径错误的“实测”比不测更坏——它会为错误结论背书。**

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 用整个文本框取样算对比度 | 把空白和背景都算成“文字底色” | 只取文字真正占据的区域，并取最坏处 |
| 假设背景图恒铺满整页 | 实际裁切、留白、蒙版都会改变底层 | 按实际 `cover/contain` 落位后合成再测 |
| 用平均亮度判断可读性 | 平均值掩盖亮暗交界处的失效 | 分别检查最亮与最暗区域 |
| 在 100% 缩放判断投影可读性 | 会议室距离下层级会消失 | 按目标距离等效缩小后再看 |
| 只看单页代表全稿 | 分页、跨页、状态变化会引入新故障 | 抽查同系统未直接修改的页面 |
| 用缩略图判断细节 | 细节问题在缩略图上不可见 | 缩略图看关系，100% 看执行 |
| 用一次去饱和截图代替全部色彩证据 | 忽略彩稿关系、实际对比、色觉类型与输出介质 | 按 `04`「色彩职责、可读性与输出校准」分层检查，灰度只作辅助 |

报告中写清取样方式、工具/环境、版本（影响结果时）、检查对象与范围。未声明的“已检查”不算证据；无范围的“已检查”等于无声明。不得跨层顶替：提示词质量不代图像质量，单页检查不代全稿验收，静帧检查不代动态验证，源文件正常不代导出正常。

### 可脚本取证的五项（复杂产物适用）

能测量的先测量，把目视判断留给关系与美感〔验〕。每项给出怎么量与失败信号：

| 项 | 怎么量 | 失败信号 |
|---|---|---|
| 文字对比 | 只取文字真实占据区域，按相对亮度公式算最坏处（纯色背景直接算；图像背景合成后取样，见上表口径） | 正文 < 4.5:1 或大字 < 3:1（采用 WCAG 2.2 AA 时） |
| 文本重叠与溢出 | 渲染后用元素包围盒相交检测；再对照裁切位/安全区 | 任意文字或关键控件相互压住、越界 |
| 派生数值回算 | 百分比、合计、增幅从同一数据源重算（容差按任务口径定，如 ±0.1 pp） | 回算对不上；回算不了的值进入结论 |
| 行长实测 | 目标宽度下实测每行中文字符数（Range/boundingClientRect 或格栅计数） | 连续阅读行长明显超出任务舒适区而未改栏宽 |
| 等效视距 | 投影/围挡场景按后排视距等比例缩小后再看层级（如 A2 围挡按 3 m 视距折算物理尺寸对比脚高） | 100% 截图通过，缩小后层级消失 |

脚本只覆盖这五项；通过它们不等于排印、构图或品牌成立，只是把可二元判定的部分先结掉，缩小目视面积。单张截图同时回答多项时只取证一次。

## 九、复跑与独立评估

需要声称“跨模型、跨任务或跨运行稳定”时，使用独立评估，而不是根据单次体验推断：

- **冻结任务包**：固定输入事实、素材、约束、目标媒介与验收判据，只改变被评估的技能版本或模型条件；任务覆盖不同媒介、复杂度、长文案与异常输入，不只选成功案例。
- **干净上下文独立复跑**，避免上一轮的候选与结论成为下一轮提示；记录模型、运行条件、失败与缺失产物。
- **预先明确判据**：事实与必要信息是否保留、P0/P1 是否识别、根因是否正确、产物是否可交付、验收范围是否覆盖主要风险。概念与构图允许多种有效答案，不把不同于参考答案判为失败。
- **盲测时隐藏版本与模型身份**，随机化呈现顺序；事实正确性与审美偏好分开报告，保留分歧。
- **结论不超出样本**：报告任务数、产物覆盖、失败与限制。单次成功、单一模型不能支持“稳定提升”。

评估集、盲测记录与对照样本留在独立开发工作区，不进入正式运行包。没有实际结果时只能提供协议，不能声称评估已执行或通过。

## 十、停止与回退

当首要目标实现、核心关系易于理解、必要事实完整、主要执行故障已处理，且继续修改的预期收益低于破坏既有成果的风险时停止。

没有改善就回退到最近的有效版本。仍可调整颜色、字体或间距，不代表必须继续修改；**终点是任务有效、结果可信，不是每个元素都更显眼。**

停止前最后自问三句：读者能复述主张吗？证据够支撑到那个程度吗？还有哪一处是我在修饰而不是在解决？

## 十一、短案例：执行层故障被当成设计层

现象：一份导出的 PDF 被反馈“文字发虚、层级出不来”。

- **错误修正**：回到设计文件，把标题加粗、字号加大、换更重的字体。结果字更糊，层级依旧，原本清晰的部分也被破坏。
- **根因**：字体未嵌入，导出时字重被替换，加粗由渲染器合成的伪粗体提供——属于**执行 / 渲染层**，不是排印层。
- **最小干预**：嵌入字体、改用真实字重、重新导出；不改字号与层级决定。对照条件：同一内容、尺寸与导出设置，只改嵌入与字重来源。
- **通过证据**：100% 下笔画边缘干净无粘连；缩到目标尺寸后三级层级仍可分辨；未引入新的溢出或断行变化。保持项：字号关系、行长、断行与页面结构不变。
- **教训**：症状出现在“字”上，不等于根因在“字”上。
