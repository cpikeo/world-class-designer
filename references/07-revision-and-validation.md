# 根因诊断、验收与停止

这是统一的修正协议。其他参考文件提供领域知识，本文件规定如何决定要不要修改、如何判断是否有效。

## 修改前四问

1. **可观察问题**：具体哪里失效？避免只写“还不够高级”。
2. **根因层级**：目标、内容/证据、概念、信息结构、构图/阅读路径、排印/色彩/媒体，还是执行/渲染？
3. **最小有效干预**：哪个改动最可能解决根因？只同时改变不可分割的必要依赖。
4. **预期证据**：改后应该出现哪种可观察变化？

无法说明问题或预期证据时，不为“继续优化”而随意改动；先补充观察或保留当前版本。

## 优先级

- **P0 交付阻断**：事实错误、误导、关键内容缺失、严重不可读、文件不可用。立即处理。
- **P1 方向/结构**：主张、概念、叙事、信息层级、主体表达不成立。先修上游。
- **P2 表现质量**：排印、色彩、图像、材质、节奏或一致性存在可见问题。
- **P3 工艺细节**：细小间距、线宽、非关键对齐和装饰；只有收益明显大于风险时处理。

## 最小修复示例

| 问题 | 错误做法 | 优先做法 |
|---|---|---|
| 标题不突出 | 同时换字体、配色、背景和文案 | 先查主张/长度、层级、占幅和位置，修改后检查首屏识别 |
| 高密度页面拥挤 | 缩小所有字号 | 重组主张与证据、分组和栏宽；最后才微调字号 |
| 图像缺乏力量 | 追加“史诗、超写实、电影级” | 诊断主体占幅、轮廓、重心、背景竞争、光向和材质，按根因裁切/局部修复/重生成 |
| 中文断行不自然 | 只调字距或把标题缩小 | 先修语义分段和文案，再调栏宽、断行和字号 |
| 多页视觉重复 | 每页更换颜色与字体 | 先重新定义页面角色，再改变焦点、尺度、密度和媒体形式，保留底层识别系统 |
| 网页在窄屏溢出 | 给页面全局加 `overflow:hidden` | 找到实际溢出源，修正局部宽度、布局或内容折行，再检查交互是否被遮住 |
| 视频动作突兀 | 给所有镜头加慢动作和转场 | 查动作起因、方向、速度、前后镜头的主体位置与时间关系 |

## 修改后判断

在相同目标、画幅、素材和渲染条件下，判断目标问题是改善、相当、退步还是尚不确定。检查副作用；无改善则回退或更换有依据的干预，不在失败修改上不断叠补丁。新证据可以来自用户反馈、渲染结果、素材/内容变化或目标变化；重复提出“还能更好”不是新证据。

## 验收与证据

先检查硬门槛：事实和语义准确、必要信息完整、关键关系未被错误表达、作品在目标媒介可用。再根据任务选择少量可观察标准。记录实际检查过的对象、环境、结果与未解决项。

- **已检查**：工具/环境确实运行过，且结果已查看。
- **部分检查**：仅检查部分页面、状态、尺寸或镜头，需说明范围。
- **未验证**：没有真实渲染、数据核对、浏览器检查或成品图可供观察。

不得把提示词质量说成成品质量，不得把检查器通过说成设计质量优秀，也不得把主观评分包装成客观测量。

## 停止条件

当首要目标实现、主张易于理解、概念成立、关键事实和执行问题已处理，且继续修改的预期收益低于破坏现有系统的风险时停止。工艺时间集中在少数真正影响理解、记忆、可信度和交付的事项上。
